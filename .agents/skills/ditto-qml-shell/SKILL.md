# Ditto QML 桌面元件

> QML／Quickshell 元件與角色：本機動畫、命中區、可替換供應者與無障礙。

> **status: draft** — 合成器能力差異表與角色命中區的實際做法在 G0-PLAT-03／G0-SHELL-03 才確定，屆時須回頭核對第 4 步並改為 stable。

## Overview

Ditto 的桌面有一個會動的角色、半透明的面板，和一套使用者可以整組替換的 UI 供應者。這三件事各自帶著一組容易寫錯的細節：動畫不能等網路、透明區域不能吃掉點擊、換掉一個 Dock 不能讓消費者跟著壞。

最需要被擋下的錯誤是把狀態表達交給動畫。角色在思考時會晃，但**任務已經停了而動畫還在晃**，使用者得到的是錯誤資訊而不是可愛。

## When to Use

用於：撰寫面板、Dock、啟動器、角色動畫、拖曳與過場、命中區；審查桌面無障礙與幀時。

不適用：

- 要不要為它開程序、常駐或輪詢 → `ditto-process-budget`。
- 這份 UI 狀態歸誰所有 → `ditto-authority-boundaries`。
- 介面文字怎麼寫 → `ditto-prose-standard`。

## Workflow

### 1. 先讀權威

打開 PRD §11 與研究文件的移植接點一節。原型已經驗證過的互動契約在那裡；本節給的是 QML 實作判準。

### 2. 動畫在本機，狀態從外面來

把兩件事分開：

- **語意狀態**（待命、思考、執行、待確認、完成、失敗、離線）由外部訂閱推送，是有界的離散值。
- **視覺過渡**由 QML 的 State 與 Transition 在本機插值。

待命動作——呼吸、眨眼、輕微晃動——**不等待任何服務**。模型斷線、Core 重啟、宿主崩潰時角色照常呼吸，因為它本來就不依賴那些。

### 3. 熱路徑不過 IPC

拖曳中的位置、動畫插值、眨眼與注視、捲動，全部留在 QML 與合成器。

- 使用者拖曳時**關閉位置過場**，讓元件直接跟隨指標；開著過場會讓它追不上。
- 佈局改變時才用過場，讓位置變化可以被視線追蹤。
- 逐幀更新不得經過 Node、模型或 Rust RPC。

### 4. 命中區：透明不攔截

角色是一張有大量透明區域的圖層。

- 命中測試依 alpha 遮罩或明確設定的 input region，**透明區域不得攔截點擊**——否則使用者會發現桌面上有一塊「點不到東西」的區域。
- 原生應用可以覆蓋角色。被遮住時必須有快捷鍵可以喚回對話，不能只靠點角色。
- 游標進入互動區才有注視與靠近反應。**全域跟隨只在合成器介面可行時啟用**；做不到就限定在互動區內並如實說明，不要靠提高輪詢頻率硬做。

### 5. 狀態必須同時有文字

六種狀態都要有可辨識的視覺**與文字**表達。

- **不得只靠晃動或顏色傳達結果。** 色覺差異、減少動畫、螢幕閱讀器使用者都必須拿到同樣的資訊。
- 任務停止 → 動畫**立即**停止。持續播放思考動作來掩蓋已停止的任務，是 AVA-04 直接禁止的。
- 無角色模式（使用者關掉角色）下，所有對話操作仍須完整可用。

### 6. 尊重偏好與焦點

- 系統的減少動畫偏好與應用內設定都要生效。
- 鍵盤焦點順序正確，所有操作有鍵盤路徑。
- 玻璃與半透明效果要兼顧可讀性；提供降低透明度與低效能替代樣式。
- 角色可移動、縮放、隱藏、停用動畫。

### 7. 供應者要可替換

Dock 與啟動器各有至少兩個供應者，這不是展示，是可組合性的證明。

- 元件透過契約掛載，消費者依能力而非實作。
- 替換供應者時不得出現重複快捷鍵或重複命令——註冊的擁有與清理見 `ditto-cordis-plugin`。
- 布局策略（浮動、基本平鋪）同樣可替換。

### 8. 合成器能力要誠實

合成器做不到的操作回傳 `unsupported`，UI 據此顯示真實可用性。

- 不要為了介面完整而顯示一個按下去沒反應的按鈕。
- 跨應用一致外觀只涵蓋 Ditto 自有介面與明確支援的裝飾，**不承諾重繪第三方應用**。
- 顯示器消失後，視窗與角色必須回到可見範圍。

### 9. 驗證

- 幀時取樣：指定操作期間至少 95% 的幀 ≤16.7 ms（NFR-05）。
- 元件隱藏後確認渲染與輪詢停止。
- 在角色透明區域點擊，確認事件穿透到底下的應用。
- 開啟減少動畫後重跑互動流程，確認所有狀態仍可辨識。
- 只用鍵盤完成一次完整的對話改造流程。
- 拔掉一個螢幕，確認視窗與角色回到可見範圍（AT-13）。
- 替換 Dock 與啟動器供應者，確認視窗存活且無重複註冊（AT-04、AT-12）。

## Calibrated Examples

**角色要在模型思考時晃動** → 晃動由「思考」這個語意狀態驅動，狀態由 Agent 回報。**不要**用「送出請求後開始晃、收到回應後停止」的做法：請求失敗或連線斷掉時它會一直晃下去。狀態機要有離線與失敗的終止路徑。

**面板想用毛玻璃背景** → 可以，但文字對比要達標，且要有降低透明度的替代樣式。半透明是預設風格，不是可讀性的例外條款。

**視窗拖曳有點卡** → 先確認拖曳期間位置過場已關閉，且位置更新沒有經過 RPC。若位置來自訂閱推送而不是本機指標事件，那是架構問題，調參數不會好。

**「這個狀態用顏色區分就夠了，很明顯。」** → 不夠。AVA-08 要求不靠顏色單獨傳達結果。加一行文字或圖示；這同時讓螢幕閱讀器與截圖裡的狀態可讀。

**使用者把角色關掉了，對話怎麼開？** → 快捷鍵與 Dock 入口都必須在。無角色模式不是降級模式，所有對話操作要完整可用。把入口綁死在角色上是 AVA-07 直接擋下的設計。

**想讓角色的眼睛跟著游標跑遍整個桌面** → 先確認合成器給不給全域游標位置。給 → 可以做。不給 → 限定在角色互動區內，並在文件裡說明這是合成器能力限制，**不要**用高頻輪詢去模擬。

**原生應用蓋住角色時，把角色提到最上層** → 反例。原生應用可以覆蓋角色，這是刻意的；角色不是永遠置頂的浮層。被遮住時的入口是快捷鍵。
