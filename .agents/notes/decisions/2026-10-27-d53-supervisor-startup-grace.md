## 結論

`ditto-supervisor` 對每一代剛武裝的 Shell 給 60 秒啟動寬限：寬限內要連續 10 次無回應（約 19～21 秒）才判定無回應；寬限結束後維持 [plan/03/05 §3](../../../plan/03/05-platform-supervision-and-rescue.md) 的連續 3 次（約 6～7 秒）。門檻依每次無回應被觀察到的時間決定，連續次數跨過寬限結束不歸零。新的一代在兩種情況開始：觀察到不存在、尚未武裝或已觸發之後的 `pong`（不論對端）；或已武裝時，回 `pong` 的連線對端**可證明**是另一個程序（`SO_PEERCRED` 的 PID 不同，或 PID 相同而兩次都讀到的程序啟動時間不同）。身分規則是「除非可證明不同，否則視為同一個程序」：讀不到對端或讀不到啟動時間都視為同一代，失敗方向是寧可進入救援。

## 依據

- [#226](https://github.com/relvo-labs/Ditto/issues/226) 的重現：v0.7.0-preview.1 安裝後的磁碟在 QEMU TCG 上登入即進入救援（`reason=shell_unresponsive`），journal 顯示武裝後約 8 秒就以 3 次規則觸發；KVM 五組設定都正常。
- 拿掉觸發後以 200 ms 間隔量 ping 往返（TCG）：Core handshake 前後停頓 6.1 秒，開機供應者 commit 後停頓 5.1 秒，再接 2.05 秒、1.09 秒的慢回覆，約 25 秒後穩定在 0.3 秒以下；KVM 最大 0.5 秒。以 1 秒期限、2 秒間隔計，最長可能連續約 5 次無回應。
- 10 次約為最長單次停頓的 3 倍、最長慢回覆區間的 2 倍；60 秒約為所有實測停頓結束時間的 2 倍以上。寬限長度只決定套用哪個門檻，不影響卡死的上限。
- 修正前，第一次回 `pong` 之前卡住的 Shell 本來就不在 supervisor 的 6 秒範圍內（README 交給 Core 的啟動就緒檢查）；這次把剛武裝後的啟動期改為有界的較寬門檻，而不是放任。

## 考慮過但沒選的方案

- 全面把 `--misses` 調高：會放寬常態期，違反 NFR-08 的 10 秒，也違反「量測不得自我放寬」。
- 等 Shell 回報 `shell.report` 或開機 commit 完成才武裝：supervisor 要依賴 Core 或 Shell 的狀態，違反 supervisor 獨立於被監督者；且第二次停頓就在開機 commit 之後。
- 寬限內完全不觸發：寬限結束後仍會以 3 次規則觸發，所以不是「永遠不進救援」；但剛武裝就卡死的 Shell 要等寬限結束才處理，從武裝起超過 60 秒；10 次門檻則約 21 秒。卡死上限也會跟著寬限長度走，要拉長寬限就得一起拉長卡死時間。
- 跨過寬限結束的連續無回應沿用啟動門檻：寬限邊界附近卡死的 Shell 會得到比常態寬鬆的處理，常態規則被變相放寬。
- 以觀察到「不存在」來判斷新的一代：Core 重啟 Shell 的最短退避是 1 秒，比 2 秒的 ping 間隔短，新 Shell 可能在 supervisor 看到「不存在」之前就接上。舊連線斷掉、重連到新 Shell 只會得到一次無回應，新 Shell 會沿用舊的常態期，在慢機器上啟動停頓仍會被殺（PR #227 審查 P1）。
- 讀不到對端時，每條連線各算一代（PR #227 第二輪審查 P1）：同一個 Shell 反覆停頓九次再回覆一次，每次重連都重新寬限，永遠到不了常態期也湊不到 10 次，等於放寬常態規則。不確定是不是同一個 Shell 時，寧可進入救援。
- 以「對端資料完全相同」判斷同一個程序（PR #227 第三輪審查 P1）：同一個 PID 有時讀得到啟動時間、有時讀不到，就會被當成不同程序，同一個 Shell 反覆停頓又回覆時可以一直重新寬限。改為只有可證明不同才算新的一代，並以窮舉測試確認同一個 Shell 不論怎麼被觀察，結果都和正確辨識相同。
- 讀 Core 寫的 `shell.pid` 判斷新的一代：要依賴 Core 寫檔的時機，而且檔案指向的不一定是回 `pong` 的那個程序；從連線本身讀對端較直接。
- 降低 Shell 主執行緒停頓（供應者非同步載入等）：是根本改善，但改動 Shell，另開 follow-up；supervisor 仍需要對慢機器有容忍。

## 影響

- `crates/ditto-supervisor`：新增 `--startup-grace-ms`（預設 60000，0 為關閉）與 `--startup-misses`（預設 10，不得小於 `--misses`）；日誌以 `phase` 區分 `startup` 與 `steady`，以 `peer` 記錄對端，並記 `grace_ended`。既有旗標與預設不變。
- plan/03/05 §3「Shell 無回應」一列加上例外。常態期與 NFR-08 不變；啟動寬限內卡死到觸發的上限約 21 秒，救援介面啟動時間另計。這段時間只有單元測試證據，VM 驗收由 #226 追蹤。
- 同一個 Shell 不能延長自己的寬限：重連後對端 PID 不變，仍是同一代。
- 讀不到對端（`getsockopt` 失敗，或 PID 為 0）或讀不到啟動時間時，無法證明是另一個程序，視為同一代，日誌記 `peer="unknown"` 或只有 PID。方向是寧可進入救援：無法分辨的快速替換可能拿不到寬限而被誤判；但同一個 Shell 不論怎麼被觀察，都不會靠重連重新寬限而永遠不觸發。
