## 修正與原因

- PR #40 多項 check 在 checkout 就失敗，尚未執行測試。[原始失敗](https://github.com/relvo-labs/Ditto/actions/runs/38442749237/job/115453228700) 指向上一個 VM run 收回的 `0500` 套件目錄。VM 收集改用共用 collector，只調整接收副本的 owner 權限；原始 guest 套件、內容與時間戳不變。非 VM 整合在私有 fixture 停止後也恢復該 store 的 owner 寫入權限。新增來源 `0500／0400`、內容比對及接收副本刪除回歸，並補 CI 觸發路徑。
- 修復預算原先沒有執行 plan/05 的「無關卡進展就停」。現在從持久父版本報告比較連續通過關卡，無進展／退步停止；同回合不能改接舊父版本或換插件 ID 繞過。原三輪與同錯兩次規則保留，明確的新使用者回合可另啟預算。Agent 指引、skill 與邊界文件同步。
- 新增 `full／partial／unavailable／未知值` 四份 Rust／TS 共用驗證報告向量；未知等級拒絕，`partial` 可解碼但無發布資格。
- 真模型 oracle 補上實際 Shell 面板與服務回讀、實際工作區按鈕點擊，以及組合／設定／授權的獨立清理與回讀。任一清理失敗不會跳過其他清理步驟，也不會報測試成功。
- 原生五關補上實測起訖與單調耗時，保存於既有 diagnostics；關卡開始即回報 phase。未執行關卡不造時間，時間也不混入錯誤指紋或發布閘門；兩類原生整合共 27 項通過。此量測補強在真模型 run 之後另跑原生整合與 VM，不把不同 runner hash 混為同一版本。

既有 CI runner 的精確失敗證據目錄另已恢復 40 個目錄的 owner 寫入權限，沒有刪除或修改證據內容。尚未推送本機修正或重跑遠端 checks，不能宣稱 PR #40 已全綠。
