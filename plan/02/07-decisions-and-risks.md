`milestones/01/05` 的 R-01～R-20 涵蓋全程。以下是在 G0 期間會實際發生、且有預先承諾備案的幾項：

| ID | 風險 | 徵兆 | 預先承諾的處理 |
| --- | --- | --- | --- |
| G0-R1 | **硬體交期超過 3 週** | W3 結束仍無參考機 | VM 上繼續 CORE／契約開發；**所有數字暫不產生**，每週進度明示此狀態；若 W5 仍未到位，出口評審中 EX-04／05／09 列為未通過並提出時程修正，不得以開發機數字替代 |

| G0-R3 | **C-04／C-05 只能經專屬 IPC** | 探針結果 | 在能力描述子的 `availability` 如實標記綁定關係，並把重寫成本寫進 D-02 的「影響」欄；C-05 轉接成本超過 2 人週時依 D-02 比較備案 |

| G0-R8 | **G0 悄悄長出配置層** | 出現任何寫入 `$XDG_CONFIG_HOME` 的程式碼 | code review 直接擋下；[01 §3.2](01-scope-and-exit-criteria.md#32-會很想做但不能做的邊界案例) 是合併判準的一部分 |

## 3. 換合成器的觸發與代價

這是 G0 唯一可能改寫後續計畫的事件，因此判準與流程要預先寫死：

| 階段 | 動作 |
| --- | --- |
| 觸發 | 探針結果符合 [02 §5.1](02-platform-and-compositor.md#51-預先承諾的判準) 的「換合成器」條件 |
| 24 小時內 | 在備案合成器上重跑探針套件（不改程式碼） |
| 3 天內 | 產出備案的能力差異表，兩份表並列比較 |
| W4 | 依兩份表做 D-02，紀錄必須包含「考慮過但沒選」一節，列出被放棄的候選與原因 |
| 之後 | 更新 `milestones/01/05` 的 D-02 與 R-01；重估 G1 的轉接成本並回寫 §3.2 的假設 |

**不做的事**：為了避免換合成器而自寫合成器外掛來補阻斷級缺口。阻斷級缺口代表該合成器與 Ditto 的假設不合，補它等於接手維護一個合成器。

## 4. 決策程序

每項決策落定時：

1. 寫 `.agents/notes/decisions/YYYY-MM-DD-<slug>.md`，五個欄位齊全（決策日期、狀態、決策者、結論、依據、考慮過但沒選的方案、影響）。
2. **「依據」必須指向數據或評估結果的位置**，不是結論的複述。「評估後認為可行」不算依據。
3. 回寫 `milestones/01/05 §2` 的對應列：決策日期、結論摘要一行、指向紀錄檔。
4. 只做其中一邊都不算完成。

未達標的指標走同一程序，但多一步：先記錄實際數據與量測條件，再分析原因（實作問題／量測方法問題／目標本身不合理），最後才提調整提案。**三件不得做的事**：把程序移出統計範圍、改變暖機或採樣條件直到數字好看、直接把門檻改成當前數字然後標記通過。

## 5. 對權威文件的回饋

G0 期間若發現 PRD 與 `milestones/01` 矛盾、或某項原則無法寫成可判斷的判準：

1. 記入 `plan/01/05` 的回饋清單（日期｜情形｜來源位置｜處理狀態｜結論）。
2. **不得自行在本計畫或程式碼裡裁決**——那會產生第三份互相矛盾的權威。
3. 裁決後更新對應權威文件，並留決策紀錄。

已知的一項待回饋：`milestones/01/03` 的 G0 工作分解沒有真機 runner 工作項，但 `04-verification §4` 要求 G0 的效能數字必須在實體參考機產生。本計畫以 G0-PLAT-05 補上，並將此矛盾登記為回饋項。
