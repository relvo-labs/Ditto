# 04｜Quickshell 工作階段與角色層

> 對應工作包：G0-SHELL-01～04。開工前讀 `ditto-qml-shell` 與 `ditto-process-budget`。

`ditto-qml-shell` 目前是 `draft`，它自己標明「合成器能力差異表與角色命中區的實際做法在 G0-PLAT-03／G0-SHELL-03 才確定」。**G0 結束時要回頭核對該 skill 的第 4 步並提出轉 `stable` 的判定**，這是 G0 對 `.agents` 的交付義務之一。

## 1. 交付範圍

| 交付 | 內容 | 不含 |
| --- | --- | --- |
| 可登入的工作階段 | 背景、layer-shell 頂部面板、底部中央 Dock、工作區指示、執行中視窗清單 | 啟動器、通知、音量網路狀態、設定介面 |
| 角色層 | 分層素材、呼吸、眨眼、注視、點擊回彈 | 六態語意狀態機（G2）、移動縮放隱藏（G4） |
| 接線 | 狀態訂閱、命令呼叫、快照重連 | 對話面板、變更卡 |
| 主題 | 支撐上述元件所需的 token 最小集 | 完整柔光果凍 token 系統（G1-SHELL-01） |

## 2. 結構

```
shell/
├─ shell.qml              Quickshell 入口：宣告各表面
├─ core/
│  ├─ DittoClient.qml     IPC client 單例：握手、訂閱、命令、重連
│  ├─ WindowModel.qml     視窗清單投影（快照＋事件）
│  ├─ WorkspaceModel.qml  工作區投影
│  └─ RpcCounter.qml      熱路徑驗證用的呼叫計數器（見 §7）
├─ jelly/
│  ├─ Tokens.qml          顏色、圓角、陰影、字級、間距、動畫時長
│  └─ Surface.qml         半透明面板基底元件
├─ avatar/
│  ├─ Avatar.qml          角色組合與狀態
│  ├─ layers/             分層素材
│  └─ FrameProbe.qml      幀時取樣（見 05 §4）
└─ providers/
   ├─ panel-top/          頂部面板
   └─ dock-bottom/        Dock（G0 只有一個供應者；第二個在 G1）
```

G0 只做**一個** Dock 供應者。DES-10 要求的兩組供應者是 G1-SHELL-03；在 G0 硬做第二個，會在能力契約還沒定案前就把可替換性寫死。

## 3. 主題 token 最小集

G0 需要的 token 僅限於支撐面板、Dock 與角色：

| 群 | 內容 |
| --- | --- |
| 顏色 | 背景、面板底色、前景文字、強調色、邊框；**每個顏色同時定義降低透明度版本** |
| 材質 | 面板模糊半徑、透明度、邊框亮度 |
| 形狀 | 圓角半徑（大／中／小） |
| 字 | 字級三階、行高 |
| 間距 | 四階 |
| 動畫 | 時長三階、緩動曲線；**以及「減少動畫」時的替代值** |

兩條約束從一開始就要成立，補做很貴：

- **降低透明度與低效能替代樣式不是之後再加的選項。** token 定義時就要有第二組值，否則所有元件都會寫死在半透明假設上（DES-11、11.1）。
- **減少動畫是 token 層的開關**，不是每個元件各自判斷。

## 4. 角色層（G0-SHELL-02）

### 4.1 素材

來源是 `apps/desktop-prototype/public/ditto-body.png`（凍結原型的素材）。G0 要把它拆成可獨立動畫的層：

| 層 | 用途 | 動畫 |
| --- | --- | --- |
| 身體 | 主體 | 呼吸（緩慢縮放）、果凍晃動（輕微形變） |
| 眼睛 | 注視與眨眼 | 眨眼（不等間隔）、瞳孔位移 |
| 嘴 | 表情 | G0 靜態，保留接點 |
| 陰影／高光 | 材質 | 隨身體形變 |

素材處置要同時登記授權來源（`ditto-release-audit`：角色素材屬於發行前必須釐清權利的項目，G0 只負責登記來源，不做法律判斷）。

### 4.2 動畫在本機

Qt Quick 的 `State` 與 `Transition` 負責所有插值。判準很單純：

> **拔掉 Core，角色仍然照常呼吸。**

G0 要實際驗證這件事：終止 `ditto-core`，確認角色動畫不中斷、不報錯、不卡住。這是 AVA-01「動畫在本機運作，不等待模型」的最小證明。

### 4.3 G0 允許哪些狀態

| 狀態 | G0 做嗎 | 理由 |
| --- | --- | --- |
| 待命（呼吸、眨眼、晃動） | 做 | AVA-01 |
| 注視（游標進入互動區） | 做 | AVA-02；**全域跟隨只在 C-02／合成器提供全域游標位置時啟用**，否則限定互動區並如實說明 |
| 點擊回彈 | 做 | AVA-03 |
| 思考／執行／待確認／完成／失敗／離線 | **不做** | 沒有任務就沒有這些狀態。AVA-04 禁止用動畫表示不存在的狀態 |

若為了展示需要思考態，只能出現在明確標示的測試夾具中，且不得進入預設工作階段。

### 4.4 文字等價從第一天開始

角色目前表達的狀態必須同時有文字形式——即使 G0 只有「待命」一種。做法是：狀態值是元件的公開屬性，旁邊的文字標籤（或無障礙 name）直接綁定它，而不是各自寫死。這樣 G2 加入六態時，文字會自動跟上，不需要回頭補（AVA-08）。

## 5. 命中區（G0-SHELL-03）

角色是一張大面積透明的圖層。透明區攔截點擊，使用者會發現桌面上有一塊「點不到東西」的區域。

| 步驟 | 內容 |
| --- | --- |
| 1 | 由素材的 alpha 通道產生命中遮罩（建置期產生，不逐幀計算） |
| 2 | 以 `wl_surface.set_input_region` 設定輸入區（對應 [02](02-platform-and-compositor.md) 的 C-07） |
| 3 | 驗證：在透明區點擊，下層應用**實際收到**事件 |
| 4 | 驗證：在不透明區點擊，角色收到事件且下層沒收到 |
| 5 | 被原生應用覆蓋時，以快捷鍵喚回（G0 只需證明快捷鍵路徑存在） |

### 5.1 驗證怎麼做

不能靠肉眼。腳本化做法：在角色透明區底下放一個會記錄點擊的參考應用（終端執行一個回報座標的程式），以合成器可用的輸入注入工具送出點擊，檢查該應用的輸出。

### 5.2 降級

若 C-07 探測結果為「部分支援」（例如 input region 只支援矩形），降級順序固定：

1. 以多個矩形近似 alpha 遮罩。
2. 若仍不可行，可保留單一矩形命中區 ＋ 快捷鍵入口供診斷，但透明區點擊穿透未通過，C-07 屬阻斷缺口；依 D-02 的判準評估備案合成器，不能把此降級當作 G0 出口通過。

**不得**用提高輪詢頻率或全域事件攔截來模擬，那會同時破壞熱路徑禁令與其他應用的輸入。

## 6. 狀態訂閱與命令（G0-SHELL-04）

| 規則 | 做法 |
| --- | --- |
| 先快照再事件 | `DittoClient` 訂閱後先套用快照，再依 `seq` 套用事件；`seq` 不連續即重新訂閱 |
| 不輪詢 | 視窗與工作區一律來自事件。要加輪詢必須先證明該狀態沒有事件來源，並在程式碼註解寫下理由（RUN-07） |
| 隱藏即停止 | 元件不可見時停止動畫、停止非必要的模型更新。Dock 被全螢幕視窗遮住時不應繼續重繪 |
| 重連 | Core 不可用時，UI 顯示真實狀態（「桌面服務未連線」），**不假裝有資料**；角色動畫不受影響 |
| 錯誤呈現 | `unsupported` 在 UI 上表現為該操作不可用，不是按下去沒反應 |

## 7. 熱路徑的機械化驗證（EX-04 的第二條判準）

「不得逐幀經 IPC」如果只靠 review，會在某次為了修一個小問題時被破壞。G0 把它變成可執行的檢查：

| 元件 | 做法 |
| --- | --- |
| `RpcCounter.qml` | `DittoClient` 的每次請求都遞增計數器，並可由外部重設與讀取 |
| 驗證腳本 | 重設計數 → 執行互動腳本（角色待命 10 秒、游標掃過角色 10 秒、拖曳一個視窗 10 秒、切換工作區 5 次）→ 按時間段與操作來源讀取計數 |
| 判準 | 待命、游標互動、拖曳與工作區切換動畫期間的請求數各為 **0**；5 次明確的工作區切換各至多 1 個語意命令請求，另列於報告。任何逐幀請求均不通過 |
| 失敗處理 | 任一被動或動畫時間段計數 > 0，或語意命令超過每次 1 個，即找出呼叫點。**不是調整判準** |

把「拖曳視窗」納入腳本時要注意：拖曳期間的位置更新應該留在合成器；若 Ditto 的 Shell 參與了拖曳，位置過場必須關閉，讓元件直接跟隨指標。

## 8. 合成器能力要誠實

Shell 啟動時讀 `desktop.capabilities.list`，依 `availability` 決定顯示什麼：

- 不可用的能力，對應的 UI 入口不顯示或明確標示為不可用。
- 不顯示一個按下去只會回 `unsupported` 的按鈕。
- 跨應用一致外觀只涵蓋 Ditto 自有介面；不承諾重繪第三方應用。

## 9. 無障礙最低集（G0）

完整無障礙是 G4-SHELL-03，但以下四項在 G0 就要成立，否則之後是重寫而不是補上：

1. 所有狀態同時有文字表達（§4.4）。
2. 鍵盤可達：面板與 Dock 的每個可操作項都有鍵盤路徑與可見焦點。
3. 系統的減少動畫偏好生效（token 層開關）。
4. 不靠顏色單獨傳達結果。
