# 01｜範圍與出口門檻

## 1. 必須交付與階段邊界

G2 完成 PRD CON-01～11 的對話路徑與相應生命週期、安全功能。繁中／英文、多輪、跨布局／插件／行為三類配置、保存／複製／切換／比較／撤銷，都必須使用真實模型和目前桌面的正式能力。

圖片作為提示、語音、自由生成插件、通用 shell／程式執行工具、第三方隔離宿主、完整發行與八小時全產品長跑不在 G2。截圖的**授權與取得**屬 G2 上下文；模型視覺理解仍依 CON-12 的 P1 範圍，文字模型不能假稱看懂圖像。未支援的生成需求指出 G3 缺口，不在主 Shell 執行新程式碼。

允許的改造路徑依序為配置修改、已安裝插件組合。第三順位生成與第四順位外部工具在 G2 必須如實顯示尚未提供；已有、可安全安裝的套件可以經既有安裝能力與授權進入組合，不能把不存在的插件當已安裝。

## 2. 開工條件與前階段追蹤

G0／G1 已依 D-38 完成，無須再等全套歷史證據。M0 可立即開始：讀取目錄、Profile、授權與 ChangeSet 契約，建立 Agent dependency spike 與 Rust 契約提案。M1 優先用 Codex 個人訂閱登入，需要有效登入、可用模型與測試配額；一般 API 路徑才需要秘密引用。這些是外部依賴，缺少時可做契約／adapter／UI，不能用 mock 計入真實語意通過率。Codex 必須完成 EX2-19，不能用另一家 API 通過替代。

## 4. 完成主張的界線

可以主張「G2 完成」的前提是上列逐項評審，或另有 owner 接受偏離的明確決策。D-38 只適用 G0／G1，不能自動套用到 G2。固定語句的 parser、替身回應、只跑單元測試、沒顯示的配置 hash，均不能取代真實模型、真實桌面與原生應用回讀。
