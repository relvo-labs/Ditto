## G0｜原生可行性

**目標**：在固定平台上證明 Quickshell＋Rust＋Wayland 能真的管理原生應用，量到第一組資源數字，並凍結後續所有階段依賴的技術基線。

**這個階段不做**：任何 LLM、任何生成、任何完整的 Profile 系統。

### 交付物

1. 支援矩陣與可重建的參考環境映像。
2. **合成器能力差異表**（每項桌面能力：支援／部分支援／不支援／需轉接）。
3. 可登入的最小桌面工作階段，能啟動並操作原生瀏覽器、終端、編輯器。
4. `ditto-core` 最小 IPC 與型別產生管線。
5. 第一份 PSS 分層量測報告與核定的初始預算、工具配額。

### 出口門檻

以下為原計畫驗證清單；2026-10-07 的 G0 階段接受與九項逐項處置見 [G0 評審 §7](../../.agents/notes/gate-reviews/G0-exit.md#7-2026-10-07-owner-階段接受)。

- [ ] 原生瀏覽器、終端、編輯器可啟動、聚焦、移動、關閉；不支援的操作明確回傳 `unsupported`（DES-01～03 基礎）。
- [ ] 合成器缺口已確認並有書面處理方案；若 Wayfire 缺口過大，**在此門檻做出合成器決策**。
- [ ] `ditto-shell` 重啟期間，參考應用零非預期終止（NFR-09 的 G0 版本）。
- [ ] 角色動畫在參考機達 60 fps 目標，且不經 IPC 熱路徑（NFR-05 初測）。
- [ ] 初始 PSS 分層預算與工具配額經有紀錄的決策核定（19.1）。
- [ ] 契約型別產生管線在 CI 上驗證通過。

### 風險與備案

| 風險 | 備案 |
| --- | --- |
| Quickshell 未整合 Wayfire（已知：其清單為 Hyprland／i3／Sway） | 撰寫 Ditto 自有 Wayfire 轉接；若成本過高，改採 Sway 或 Hyprland 並更新 PRD 25 節決策 |

## G1｜組合底座

**目標**：在**完全沒有模型**的情況下，使用者能以 GUI 完成跨插件替換、保存組合、比較差異、撤銷與故障回復；Cordis 桌面服務真的在跑，且 Agent 不存在也不影響。

這是最大也最關鍵的階段。G3 不可繞過本階段。
